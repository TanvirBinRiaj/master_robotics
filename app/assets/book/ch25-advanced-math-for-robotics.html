1. Why robots need better math

Imagine you tell a robot arm to pour tea. The cup must stay upright while the arm moves. A small error spills hot tea everywhere. Simple school math is not enough here. You need a math that respects turns and limits.

Think of a door hinge. It only turns one way. You cannot describe it with one plain number. You must say which way it points. Robots are full of hinges like this. Each joint adds a new turn to track.

Now think of planning like shopping on a budget. You want the best food for the least money. You also have rules, like no nuts for allergies. Robot control works the same way. You want the best motion under strict rules.

What this chapter gives you

First you learn how to talk about turns. Then you learn how to talk about poses. Finally you turn whole tasks into math puzzles. Each puzzle has one best answer. A fast solver finds it for you.

If you know kinematics and PID control, you are ready. If not, read those chapters first. They give you frames and feedback in simple form.

In plain English

A Lie group is a smooth family of moves. You can join two moves into one. You can also undo any move. Turns and poses both form such families.

2. Rotations live in SO(3)

A rotation turns a thing without stretching it. Lengths stay the same after a pure turn. Angles between lines also stay the same. That is the whole idea in one line.

SO(3) is the name for all 3D turns. SO means special orthogonal group. The 3 means three dimensions. Think of it as a club with strict entry rules.

To join the club, a 3 by 3 matrix must pass two tests. Its columns must have length one. Its determinant must equal plus one. A mirror fails the second test. So mirrors are not rotations.

The three rules of a rotation matrix

First, each column is a unit arrow. Second, columns stand at right angles. Third, the handedness stays right-handed. Your right hand is a good model. Thumb, finger, and middle finger show the axes.

This sounds fussy, but it protects you. Bad matrices squash your robot model. Good matrices only turn it. The solver trusts a true rotation. So you should check these rules often.

2D rotation R(θ) = [cosθ −sinθ ; sinθ cosθ]
Rotation test Rᵀ × R = I and det(R) = +1
Note

Never average two rotation matrices entry by entry. The result is often not a rotation. It can stretch and shear. Blend quaternions instead, then convert back once.

3. Quaternions: turns without tears

A quaternion stores a turn in four numbers. One number sets the amount of turn. Three numbers set the axis of turn. It is like saying "turn this much around this stick".

Think of a spinning top. The stick is the axis. The spin amount is the angle. A quaternion packs both ideas together. It uses less memory than a matrix. It also blends smoothly between poses.

Rotation matrices have nine numbers with six rules. Quaternions have four numbers with one rule. The rule is simple: the length must equal one. That is why games and robots love them.

The only rules you must memorize

First, a unit quaternion has length one. Second, q and −q give the same turn. Third, you multiply quaternions to chain turns. Order matters, just like putting on socks and shoes.

  • Identity turn: q = [1, 0, 0, 0]. Nothing moves at all.
  • 180-degree trap: near half turns, pick the shortest path.
  • Always normalize after each math step. Small drift grows fast.

4. Poses live in SE(3)

SE(3) means all rigid poses in 3D. Each pose has a turn plus a shift. Think of moving a coffee mug. You turn it and slide it. That full move is one SE(3) pose.

A pose matrix is 4 by 4. The top-left holds the SO(3) turn. The top-right holds the shift in x, y, z. The bottom row is fixed. This layout lets you chain moves by multiplication.

The exponential map turns small twists into poses. A twist is like a short speed command. It says "spin this fast and move this fast". Apply the map and you get a real pose change.

How to think in steps

  1. Start from the current pose of the hand.
  2. Pick a small twist for one short time step.
  3. Use the exponential map to get the new pose.
  4. Repeat many small steps to draw a smooth path.

This is how smooth planners think. They do not jump far. They stack many tiny safe moves. Each move stays close to the true curved space.

Tip

Store poses as position plus quaternion in code. Convert to a 4 by 4 matrix only for math. This keeps memory small and blends smooth. See kinematics for frames first.

5. Worked example: rotate a point step by step

We now turn the point (1, 0) by 90 degrees. This is a 2D turn in the flat plane. We show each number so you can follow. You only need a pocket calculator.

Step 1: write the angle in numbers

Angle θ = 90°. So cosθ = 0 and sinθ = 1. These are exact values for a square corner. No rounding is needed here.

Step 2: build the matrix

Put the values into R(θ). The top row becomes [0, −1]. The bottom row becomes [1, 0]. Check the rules now. Each column has length one. The determinant is 0 × 0 − (−1) × 1 = 1.

Step 3: apply it to the point

New x = 0 × 1 + (−1) × 0 = 0. New y = 1 × 1 + 0 × 0 = 1. So (1, 0) moves to (0, 1). The point moved from east to north. That is a correct left turn.

Step 4: sanity check

  1. Length before: √(1 + 0) = 1.
  2. Length after: √(0 + 1) = 1.
  3. Lengths match, so no stretch occurred.
  4. Determinant is +1, so no mirror occurred.

Try 180° on your own next. Cos is −1 and sin is 0. Point (1, 0) should land on (−1, 0).

Python 
import numpy as np

def quat_from_axis_angle(axis, angle_rad):
    axis = np.asarray(axis, dtype=float)
    axis = axis / np.linalg.norm(axis)
    w = np.cos(angle_rad / 2.0)
    xyz = axis * np.sin(angle_rad / 2.0)
    q = np.concatenate([[w], xyz])
    return q / np.linalg.norm(q)

def quat_multiply(a, b):
    w1, x1, y1, z1 = a
    w2, x2, y2, z2 = b
    return np.array([
        w1*w2 - x1*x2 - y1*y2 - z1*z2,
        w1*x2 + x1*w2 + y1*z2 - z1*y2,
        w1*y2 - x1*z2 + y1*w2 + z1*x2,
        w1*z2 + x1*y2 - y1*x2 + z1*w2,
    ])

# 90 deg about z, then 90 deg about y: order matters!
qz = quat_from_axis_angle([0, 0, 1], np.pi / 2)
qy = quat_from_axis_angle([0, 1, 0], np.pi / 2)
q = quat_multiply(qy, qz)  # apply qz first, then qy
print("q =", np.round(q, 4), " norm =", round(float(np.linalg.norm(q)), 4))

# Tiny QP-style idea: min 1/2 x^T P x + q^T x, subject to A x <= b
# P must be positive-definite (bowl shape). Then one best x exists.
P = np.array([[2.0, 0.0], [0.0, 2.0]])
qv = np.array([-4.0, -6.0])
x_free = -np.linalg.solve(P, qv)  # unconstrained answer: [2, 3]
x = np.minimum(x_free, np.array([1.5, 10.0]))  # fake clip by x1 <= 1.5
print("free:", x_free, " clipped:", x)

6. Every task is an optimization: the convex QP

A convex QP is a puzzle with one bowl. QP means quadratic program. The cost is a smooth bowl shape. Any local low point is the global low point.

Picture a soup bowl on a table. Drop a marble anywhere inside. It always rolls to the same bottom. That bottom is the best answer. Convex math gives you this promise.

The standard form looks scary but reads simply. Minimize half of xᵀ P x plus qᵀ x. Keep Ax ≤ b and Cx = d. P sets the bowl shape. The rest sets walls and rails.

Convex QP min ½ xᵀ P x + qᵀ x   s.t. A x ≤ b, C x = d
Tiny answer P = 2I, q = [−4, −6] → x* = [2, 3], clipped to [1.5, 3]

Tiny numeric example with words

Let P be 2 on the diagonal and 0 elsewhere. Let q be [−4, −6]. Without walls, the best x is [2, 3]. You find it by solving P x = −q. That is one linear solve.

Now add a wall: x1 ≤ 1.5. The free answer breaks the wall. So you slide along the wall to [1.5, 3]. That clipped point is the new best. Real solvers do this sliding for many walls at once.

Warning

P must be positive-definite for a true convex bowl. If P has a flat or upside-down bend, the solver can stall. Check eigenvalues of P before you blame the robot.

7. Optimal control and MPC in plain words

Optimal control picks the best pushes over time. It cares about the full trip, not one step. Think of driving with fuel, comfort, and time in mind. You trade them off along the whole road.

Pontryagin gives rules like traffic lights. At each moment, the best push follows a helper signal. That helper is called the costate. It tells you how precious each state is.

HJB looks at the whole map at once. It asks what the best future cost is from each spot. If you knew that map, control would be easy. But the map is too big to store exactly.

MPC: plan short, move one step, repeat

  1. Measure where the robot is right now.
  2. Plan the best short movie of the next seconds.
  3. Play only the first frame of that movie.
  4. Measure again and plan a fresh movie.

This loop is called MPC, or model predictive control. It always uses fresh sensor data. That is why it handles bumps and wind well. Short plans stay fast enough to run live.

For state guessing, teams use an EKF or a factor graph. An EKF blends model and sensors step by step. A factor graph solves many steps as one smoothing puzzle. Both feed cleaner states to MPC. See glossary for quick term refreshers.

Key idea

MPC does not trust an old plan for long. It replans every tick from new data. Short honest plans beat one long stale plan.

8. Common mistakes

Most bugs here come from small math slips. They look fine on screen but break the robot. Check this list before long tests.

  • Euler angle flips. Near straight up, angles jump wildly. Use quaternions for blending instead.
  • Forgot to normalize. A quaternion of length 1.02 slowly scales poses. Normalize after every update step.
  • Wrong multiply order. World-frame and body-frame chains differ. Test with a known 90-degree turn first.
  • Non-convex cost. A wavy cost has many fake bottoms. Start convex, then add detail only if needed.
  • Ignored units. Mixing degrees and radians breaks maps. Pick radians in code and stay with it.

9. How professionals do it

Pro teams keep math code boring and tested. They wrap SO(3) and SE(3) in one small library. Every convert function has a unit test. No raw matrix math sits in control loops.

They warm-start each QP with the last answer. Most ticks need only small changes. They also cap solve time strictly. If the solver runs long, they reuse a safe fallback.

They log P conditioning, solve times, and MPC horizons. They review plots after each run. A slow drift in solve time warns of trouble. It often means constraints fight each other.

10. Try it yourself

  1. Turn (0, 1) by 90°. Build R(90°) on paper. Apply it to (0, 1). Hint: expect (−1, 0) for a left turn.
  2. Fix a bad quaternion. Normalize [0.5, 0.5, 0.5, 0.5] and check length one. Hint: divide by its norm, which is 1.0 here already.
  3. Solve a 1D QP. Minimize x² − 6x with x ≤ 2. Hint: free answer is 3, so the wall wins at 2.
  4. Explain MPC in 30 seconds. Say it to a friend without math words. Hint: use "short movie, play one frame, repeat".

Going deeper (optional): estimation with EKF and factor graphs

Sensors lie a little. Estimation blends many lying sensors into one honest guess. Two tools rule this job.

First, the extended Kalman filter (EKF). It keeps a guess and a doubt score. Predict with the model, then correct with the measurement. Big surprise means big correction. Small doubt means trust the guess.

Kalman idea new guess = prediction + gain × (measurement − prediction)

Second, factor graphs (solved by libraries like GTSAM). Instead of one guess marching forward, keep the whole history of poses and landmarks as a web of clues. Each clue is a factor: odometry links two poses, a camera sighting links a pose to a landmark, a loop closure pulls an old place tight. Then solve the whole web at once. This is how modern SLAM gets maps that do not drift.

Tip

Remember this split: EKF for fast live pose at 100+ Hz, factor graphs for the best map when you can afford to solve the web. Real robots run both.

Key takeaways

  • SO(3) holds all true 3D turns, with no stretch or mirror.
  • Unit quaternions store turns compactly and blend smoothly.
  • SE(3) joins a turn with a shift into one pose.
  • The exponential map turns small twists into real pose steps.
  • A convex QP has one best answer solvers find fast.
  • MPC plans a short future, moves once, then replans.
Check your understanding
Q1.What two tests must a rotation matrix pass?
Answer. R-transpose times R equals I, and det equals +1.
Q2.Why do q and minus q give the same turn?
Answer. Both encode the same axis and full turn; it is a double cover.
Q3.What does SE(3) add on top of SO(3)?
Answer. A 3D shift, so a full rigid pose results.
Q4.What makes a QP convex and easy?
Answer. P is positive-definite, so cost is one bowl.
Q5.Why does MPC play only the first step?
Answer. Fresh sensor data arrives, so it replans from truth.
Q6.When should you prefer a quaternion over Euler angles?
Answer. When blending or near vertical, to avoid jumps.
Q7.When does a robot prefer quaternions over Euler angles?
Answer. When it blends orientations or turns through any pose: quaternions never hit gimbal lock, while Euler angles freeze at the poles.
Q8.What does the gain do in the Kalman update?
Answer. It sets how much the surprise moves the guess: high gain trusts the measurement, low gain trusts the prediction.
