How to use this page

This is a cheatsheet, not a lesson. Learn the ideas in Chapter 25 first. Then use this page to recall exact forms while you code.

2D rotation

A point (x, y) turned by angle θ becomes a new point. The rotation matrix is the recipe.

2D rotation x' = x cosθ − y sinθ,   y' = x sinθ + y cosθ

Example: turn (1, 0) by 90°. cos90 = 0, sin90 = 1. So x' = 0, y' = 1. The point now aims straight up.

SO(3): rotation matrices in 3D

SO(3) is the set of all 3×3 rotation matrices R. Two rules define them.

SO(3) rules R^T R = I   and   det(R) = +1

R^T R = I means the columns are unit arrows at right angles. det = +1 means no mirror flip. To compose rotations, multiply: R_total = R2 × R1 (apply R1 first).

Quaternions

A quaternion stores a rotation as four numbers: one scalar plus a 3D arrow.

Quaternion q = [w, x, y, z],   |q| = 1   (unit length)

Rotation of angle θ around unit axis (ux, uy, uz): w = cos(θ/2), (x,y,z) = sin(θ/2) × (ux,uy,uz). Always normalize after blending two quaternions, or the rotation will also scale.

NeedUse this
Store a pose on the robotQuaternion (compact, no gimbal lock)

SE(3): poses as 4×4 matrices

SE(3) packs rotation R and position p into one matrix T. It moves points between frames.

SE(3) pose T = [ R   p ; 0   1 ],   point' = T × point

Compose poses by multiplying: T_world_foot = T_world_hip × T_hip_foot. Inverse swaps the direction: R goes to R^T, p goes to −R^T p.

Exponential and logarithm maps

The exponential map turns a small 3-vector ω (axis times angle) into a rotation. The logarithm map goes back.

SO(3) exp / log R = exp(ω^),   ω = log(R),   |ω| = angle

Optimizers use this trick: store the pose as a matrix or quaternion, but take correction steps as small vectors ω. Small-angle shortcut: R ≈ I + ω^.

Quadratic program (QP)

The standard form every solver (OSQP, HPIPM, qpOASES, PROXQP) accepts:

QP form minimize ½ x^T P x + q^T x   subject to   l ≤ A x ≤ u

P must be positive semi-definite (bowl shape, one bottom). A holds limits such as friction cones and torque caps. Add a tiny regularization (ε times identity) to P if the solver complains.

Whole-body QP variables

For walking and manipulation, the decision vector stacks accelerations and contact forces:

WBC variable ξ = [ accelerations ; contact forces ],   torques from rigid-body dynamics

Priority order used in Chapter 26: physics (dynamics, friction) first, then feet and balance, then hands and gaze, then posture and comfort.

MPC loop in five lines

Python 
while robot_is_running:
    state = estimate_state()          # fuse encoders + IMU
    plan = solve_mpc(state, horizon=1.0)  # QP over short future
    apply(plan.first_step)            # torques to motors
    warm_start_next_cycle(plan)       # reuse plan, solve faster

Key takeaways

  • SO(3) stores rotations; SE(3) stores full poses.
  • Quaternions blend cleanly; always normalize them.
  • Every WBC/MPC solver eats the same QP form.
  • MPC means plan short, run the first step, replan.
